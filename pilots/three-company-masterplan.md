# Three-Company Revenue Engine Pilot Masterplan

## Mission

Prove the Booking Engine doctrine in three materially different operating environments:

1. Gabriel Health Institute
2. Montessori Bilingual Academy
3. Eola Masonic Lodge

The goal is not theoretical completeness. The goal is measurable movement through:

**Campaign → Capture → Convert → Close**

Each pilot follows the same implementation sequence while preserving tenant-specific configuration.

## Pilot outcomes

### Gabriel Health Institute
Primary outcome: **paid student enrollment**

Proves:
- high-volume consumer lead handling
- multilingual routing
- immediate admissions response
- booking and show-rate improvement
- admissions conversion
- payment/enrollment
- staff training and QA

### Montessori Bilingual Academy
Primary outcome: **enrolled family**

Proves:
- local-service / education demand generation
- multi-location routing
- parent nurturing
- tour/consultation booking
- follow-up and show recovery
- longer decision cycle

### Eola Masonic Lodge
Primary outcome: **qualified prospect advancing through the lodge's approved membership journey**

Proves:
- membership/community use case
- longer-cycle nurture
- event/inquiry conversion
- relationship-driven follow-up
- configurable nontraditional close event

## Universal rollout sequence

Every company is implemented through the same phases.

### Phase 0 — Baseline and journey map
Document:
- current campaign sources
- lead entry points
- lifecycle stages
- staff ownership
- existing tools
- response time
- contact rate
- booking rate
- show rate
- close rate
- revenue/outcome per lead where applicable
- known leakage

**Gate:** baseline can be measured and the current journey is understood.

### Phase 1 — Capture and communications
Implement:
- lead source/attribution
- forms/landing pages
- routing
- ownership
- immediate notifications
- phone/SIP/headset configuration where appropriate
- SMS/email first-touch
- response-time SLA
- missed-contact escalation

**Gate:** no new lead can silently sit without an owner or next action.

### Phase 2 — Human execution system
Implement:
- role definitions
- written SOPs
- scripts
- call dispositions
- objection handling
- training videos
- contextual job aids
- recurring coaching cadence
- recorded training library

**Gate:** staff can independently determine the correct next action.

### Phase 3 — Follow-up and booking
Implement:
- no-answer sequences
- contacted/not-booked sequences
- booking flows
- calendar rules
- confirmations
- warm-transfer rules
- task queues
- long-term nurture
- every lead has a next action

**Gate:** no active lead can enter an undefined dead state.

### Phase 4 — Show-rate acceleration
Implement Video Accelerators and reminders at relevant gates:
- post-lead
- pre-booking
- post-booking
- pre-appointment
- no-show recovery

**Gate:** booking-to-show movement is measurable and recovery exists.

### Phase 5 — Close system
Implement:
- closing SOP
- pricing/offer presentation
- close authority
- payment/enrollment/member advancement
- lost-reason taxonomy
- immediate handoff after commitment
- undecided recovery

**Gate:** final outcome is recorded and attributable back to the lead/source.

### Phase 6 — AI support and escalation
Implement:
- knowledgeable chatbot
- approved actions
- staff/customer help
- escalation to human
- ticket context preservation
- ownership of unresolved queue

**Gate:** support requests are either resolved or reliably escalated.

### Phase 7 — Reliability and self-recovery
Implement:
- workflow failure detection
- integration monitoring
- ticket creation
- automated retry where safe
- deployment/technical recovery paths
- human escalation only for real blockers

**Gate:** routine technical failures no longer depend on someone noticing manually.

### Phase 8 — Optimization loop
Weekly:
1. Find largest leakage point.
2. Diagnose strategy/software/hardware/human cause.
3. Implement one or more fixes.
4. Measure again.
5. Document learning.
6. Promote repeated needs into doctrine/platform.

**Gate:** continuous; there is always a next constraint.

## Parallelization strategy

Do not finish all eight phases for one company before starting another.

Recommended sequence:

### Wave A — Baseline all three
Complete Phase 0 across GHI, Montessori, and Eola.

### Wave B — Revenue-critical foundation
Complete Phases 1–3 across all three.

### Wave C — Conversion lift
Complete Phases 4–5 across all three.

### Wave D — Scale and resilience
Complete Phases 6–7 across all three.

### Wave E — Optimization
Run Phase 8 continuously across all three.

This keeps the learning loop comparative and prevents one tenant from overfitting the platform.

## Learning ledger

Every meaningful pilot discovery should be classified as:
- Core platform
- Configurable capability
- Tenant-specific
- Human-process issue
- Hardware/channel issue
- Strategy issue
- Measurement issue

This pilot is complete only when all three organizations are operating through the system with real-world data and the doctrine has been revised from observed reality.
