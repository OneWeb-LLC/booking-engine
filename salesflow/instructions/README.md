# Salesflow Instruction Directory

These are the employee-facing operating procedures for Salesflow. Each page must be complete enough for a nontechnical employee to perform the task without opening an abstract action standard or an external vendor article.

## Instruction standard

Every procedure should read like a written Scribe walkthrough:

1. identify when the procedure applies and the required outcome;
2. show the exact navigation path;
3. use one visible click, selection, or entry per numbered step;
4. state what belongs in each relevant field;
5. show the visible confirmation that proves completion;
6. explain what automation should happen next;
7. identify exceptions, Recoveries, and escalation;
8. include client-verified screenshots wherever a nontechnical employee could become lost.

The technical source of a feature—core Salesflow, client configuration, or a future Booking Engine Snapshot—is metadata for maintainers. It must not create separate employee instruction libraries.

## Rules

- Use the exact client-approved Salesflow labels visible on screen.
- Follow one instruction at a time.
- Do not improvise pipeline stages, dispositions, ownership, or promises.
- Do not create a second action when a valid action already exists.
- Do not mark work complete until the customer outcome and system record agree.
- Ask the Team Manager when the interface or available action differs from the instruction.

## Universal completion check

Before leaving a record, verify:

1. customer state is accurate;
2. one definitive disposition is recorded when applicable;
3. pipeline stage and status are accurate;
4. the correct appointment, task, Call Queue action, or Recovery exists;
5. meaningful context is preserved;
6. obsolete work is resolved or suppressed;
7. ownership is accepted.

## Verification state

Current click paths are framework drafts derived from the prior Staff Notebook and must be verified in the target Salesflow account. A client deployment is not complete until the Salesflow Administrator adds the approved labels, screenshots, scripts, calendars, pipelines, dispositions, permissions, and escalation contacts.
